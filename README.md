# WebGuardian 网站安全检测工具

## 🚀立即体验

无需本地部署，点击链接即可使用：

 ### [WebGuardian Streamlit](https://web-guardian.streamlit.app)

注意：请在合法授权范围内使用。检测结果会受到网络环境影响，结果仅供参考

## 项目说明

WebGuardian 是一个基于 Python 和 Streamlit 开发的网站基础安全检测工具。输入目标网站地址后，工具会执行可配置的基础站点检测、DNS 安全检查和页面级安全检查，并输出基础配置评分、本次检查范围、分项依据、风险提示、检测耗时、本次扫描过程中的基础可用性指标和原始检测数据。证据不足的检查保留未知或未完成状态，不生成确定的评分与评级。

项目定位为轻量的安全基线检查工具，不替代专业漏洞扫描、渗透测试或持续安全监测。

当前仅支持 `http` 和 `https` 协议；`file`、`ftp`、`ssh` 等非 HTTP 协议会被直接拒绝。

## 一、主要功能

### 1. HTTPS 检测

检测最终访问地址是否走 HTTPS。输入地址发生跳转时，以最终响应地址为准。

### 2. SSL/TLS 证书检测

检测 HTTPS 连接是否有效，并显示证书剩余有效天数。

最终地址使用 HTTP 时，TLS 检查标记为不适用。超时或握手失败导致某个 TLS 协议无法判定时，保留未知状态，不直接判定目标不支持该协议。

### 网站可用性观测

在本次正式请求上记录 `DNS` 解析、`TCP` 连接、`TLS` 握手、`TTFB` 和发送/接收总量，并在结果页的折叠区展示，便于查看基础响应情况。不进行并发请求或压力测试。

### 3. HTTP 安全响应头检测

检查常见安全头是否存在，并对 `CSP`、`HSTS`、`X-Frame-Options` 等配置做基础值校验。结果分别列出缺失项与无效值及原因；通过基础校验不代表策略已完成全面审计。

### 4. DNS 安全检测

检查域名的 `SPF`、`DMARC` 和 `CAA` 记录，帮助发现邮件伪造和证书签发范围过宽等问题。

DNS 查询失败与记录缺失分别处理；未取得查询结论时保留未知或部分完成状态，不能把网络错误当作记录不存在。

### 5. HTTP 方法检测

先发 `OPTIONS` 请求，再结合 `Allow` 和 `Access-Control-Allow-Methods` 判断服务器暴露了哪些方法，同时单独检测 `TRACE` 是否可用。`PUT`、`DELETE`、`PATCH` 只做暴露推断，不做副作用实测。

### 6. 敏感路径检测

检查常见后台、备份、调试和接口文档路径，如 `/admin`、`/docs`、`/api/docs`、`/swagger`、`/phpinfo.php` 等。记录疑似暴露、访问受限、重定向待确认、未发现和请求失败等响应情况，并显示已响应、失败与总路径数。空的命中列表只有在检查完成后才表示本次未发现命中；请求失败或跳转待确认会保留未完成结论。路径命中仍需人工确认，不能直接认定为漏洞。

### 7. 暴露信息检测

检查响应头和页面源码中的高信号暴露项，包括服务器/框架标识、版本特征，以及 `generator`、`application-name`、`og:site_name`、`author` 等重点 `meta` 字段。

### 8. 页面级检查

页面级检查从首页开始轻量抓取，只跟进同源 HTML 链接，并限制抓取页数和深度。可选项包括混合内容、不安全表单、Cookie 安全属性、重定向链、页面响应头、页面源码暴露信息，以及 `robots.txt / sitemap.xml` 暴露面分析。

页面结果分别统计尝试、完成 HTML 检查、失败和跳过的页数。失败请求、非 HTML 响应及跳过项不会被记为已完成的 HTML 检查；结果不完整时不显示“未发现问题”的成功结论。

### 9. 扫描模式与进度

界面提供标准、快速、深度和自定义四种模式。修改任一选项后会自动切换为自定义模式，输入 URL 后可按 Enter 直接开始扫描，扫描中也可以随时停止。

进度条按当前启用项动态计算，请求失败、非 HTML 页面或跨源跳转导致的跳过项也会补足进度。

## 二、基础配置评分与本次范围

基础配置评分只针对本次已启用且适用的基础检测项；全部取得足够证据后，按这些项的可得分归一化为 100 分。概览同时展示已启用项数（共 7 类）、已评估、未知和不适用项数，并提供各项得分、满分、状态与原因。仅开启 HTTPS 获得的 100 分只代表这一个检查项，不能据此推断整站安全。

任一已启用检查存在未知或部分完成状态时，评分与评级显示“待完成”，JSON 中 `score` 为 `null`；本次没有适用的基础评分项时显示“不适用”。页面级安全检查独立展示风险，不直接计入基础配置评分。

| 检测项 | 最高分 | 得分条件 |
|---|---:|---|
| HTTPS | 10 | 最终地址使用 HTTPS |
| SSL/TLS | 20 | 证书有效、有效期、协议与套件、证书链完整性 |
| DNS 安全检测 | 15 | SPF、DMARC、CAA 越完整，得分越高 |
| HTTP 安全响应头 | 30 | 常见安全头存在且通过基础值校验，当前重点关注 CSP、HSTS、X-Frame-Options |
| 暴露信息检测 | 10 | 未发现响应头和 meta 暴露项 |
| HTTP 方法检测 | 5 | 未发现 TRACE 可用或其他高风险方法暴露 |
| 敏感路径 | 10 | 内置路径检查完成，未发现疑似暴露路径 |

| 分数范围 | 等级 |
|---|---|
| 85 - 100 | A级 |
| 70 - 84 | B级 |
| 0 - 69 | C级 |

关闭或不适用的基础检测项不会计入可得分总分；未知和部分完成项会阻止生成正式评分。A级、B级、C级仅用于本次范围内已完成的基础配置评分。

## 三、项目结构

```text
main.py                    # 直接启动 Streamlit 应用
app.py                     # 页面流程、URL 表单和扫描调用
scanner/
  options.py               # 扫描配置模型
  scanner.py               # 主扫描编排和 ScanContext
  basescan/
    __init__.py            # 基础站点扫描入口
    availability.py        # 单次正式请求的可用性指标采集
    base_checks.py         # HTTPS、安全头、暴露信息、HTTP 方法、敏感路径
    tls.py                 # TLS/SSL 证书与配置检测
    dns.py                 # SPF、DMARC、CAA 检测
  pagecheck/
    page_scan.py           # 同源页面抓取与检查编排
    page_checks.py         # HTML 解析及页面安全检查规则
    page_results.py        # 页面发现、风险统计和结果聚合
    sitecheck/             # robots.txt / sitemap.xml 暴露面分析
utils/
  control.py               # 扫描中断信号
  net.py                   # 请求会话、URL 校验和地址规范化
  timer.py                 # 扫描耗时统计
ui/
  scan_config.py            # 扫描模式、配置控件和配置校验
  page_style.py             # 页面宽度与居中样式
  result/
    view.py                 # 扫描结果展示
runtime/
  scan_progress.py          # 按工作量计算扫描进度
  models.py                # 运行状态和运行时快照
  runtime.py               # 后台执行、停止控制和运行状态
  view.py                  # 运行状态和结果展示
  errors.py                # 错误归类与友好提示
result_model/
  models.py                # 扫描领域结果模型
  composer.py              # 后端结果包装和合成
  security_score.py        # 安全评分与等级规则
tests/                     # pytest 单元测试
requirements.txt           # 运行依赖
```

## 四、安装与运行

### 1. Python 版本要求

最低要求：**Python3.10**

项目代码使用了联合类型注解等语法，低于 3.10 的解释器不兼容。

GitHub Actions 已在 **Python 3.10 至 3.14** 运行全部单元测试；Docker 镜像使用
**Python 3.14**。

### 2. 创建虚拟环境

Windows PowerShell：

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

macOS 或 Linux：

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. 安装依赖

```bash
pip install -r requirements.txt
```


### 4. 启动应用

在项目根目录执行：

```powershell
py main.py
```
或
```
streamlit run app.py
```

`main.py` 已包含 Streamlit 启动逻辑。也可以直接执行 `streamlit run app.py`；启动成功后，终端会显示本地访问地址，默认通常为 `http://localhost:8501`。

### 5. 使用 Docker 镜像

如果希望使用Docker：

```bash
docker pull ghcr.io/fzgma/webguardian:latest
docker run --rm -p 8501:8501 ghcr.io/fzgma/webguardian:latest
```

如果镜像已经在本地，也可以直接运行：

```bash
docker run --rm -p 8501:8501 ghcr.io/fzgma/webguardian:latest
```

启动后访问 `http://localhost:8501` 即可。

### 6. 运行测试与 CI

```bash
python -m pytest tests -v
```

推送分支以及创建或更新 Pull Request 时，GitHub Actions 会在 Python `3.10`、`3.11`、
`3.12`、`3.13` 和 `3.14` 上运行全部 pytest 测试。Docker 镜像发布工作流独立于测试工作流，仅在推送 `v*` 标签时构建和发布。

结果页回归使用 Streamlit `AppTest` 验证实际组件输出，包括未完成评分、单项检查范围、无效安全头和未完成路径检测的展示；这些测试不需要访问外部目标站点。

## 五、使用方式

1. 选择预设扫描模式，或进入自定义模式。
2. 需要页面级检查时，启用该开关并至少选择一个页面子项。
3. 输入网站地址，例如 `https://example.com`。
4. 如果使用 Docker 运行，先启动容器，再在浏览器访问容器暴露的地址。
5. 按 Enter 或点击“开始检测”。
6. 在“概览”“基础检测”“页面风险”和“原始数据”中查看检测结果；原始数据页支持下载 JSON，必要时可在检测中停止任务。

首次启动后的第一次扫描可能因为 Streamlit、Python 依赖和前端组件的冷启动与预热而耗时较长；同一进程后续扫描通常会更快。

如果输入地址无效，界面会直接提示具体原因，不会开始扫描。

若所有检测项均关闭，或页面级检查未选择任何子项，应用会在开始扫描前提示修正配置。


## 六、结果架构

扫描结果采用“模块小结果 -> 统一大结果 -> 展示模型”的分层结构：

1. `scanner/scanner.py` 创建一次扫描的 `ScanContext`，保存目标地址、会话、扫描配置、进度和停止信号等运行态信息。
2. HTTPS、网站可用性、TLS、DNS、安全响应头、HTTP 方法、敏感路径、信息泄露和页面扫描分别生成独立的 section result。
3. `result_model/composer.py` 统一包装和合成结果，聚合各模块的 `warnings`、`findings` 和错误，并生成评分、等级、总耗时、模块耗时和页面扫描摘要。
4. `ui/result/view.py` 通过 `result_model/composer.py` 将扫描结果转换为展示层模型，并按“概览”“基础检测”“页面风险”“原始数据”四个 Tab 渲染。

结果页的组织方式如下：

- “概览”显示基础配置评分、本次范围、分项评分依据、HTTPS、总耗时、实际执行模块的横向耗时图、目标摘要和可用性指标。存在未知或未完成的基础检查时暂不评级。模块耗时不包含初始化、评分和结果组装等编排开销，因此不应与总耗时直接相加比较。
- 检测过程存在错误或警告时，概览顶部会显示数量提示，详细内容位于概览末尾的折叠区；没有消息时不渲染该区域。
- “基础检测”以并列区域展示 TLS/DNS 与安全头/HTTP 方法，安全头的缺失与无效配置分别说明；敏感路径提供完成情况和逐条响应记录，暴露信息保持全宽。
- “页面风险”显示尝试、完成、失败、跳过页数及结果完整性，并提供按风险等级筛选的全宽表格；“原始数据”保留 JSON 浏览并支持下载 JSON 文件。

成功扫描结果的顶层结构如下：

```text
{
  "target": {...},    # 输入地址、规范化地址、主机和解析 IP
  "checks": {...},    # 各检测模块的独立结果
  "summary": {...},   # 可空评分、等级、scoring 范围与分项依据、耗时和页面扫描摘要
  "errors": [...],    # 检测过程中的错误
  "warnings": [...]   # 检测过程中的警告
}
```

`summary.scoring.status` 为 `complete`、`partial`、`unknown` 或 `not_applicable`；`items` 中每个基础项保留 `earned`（未知时为 `null`）、`maximum`、`status` 和 `reason`。页面扫描中的 `pages_scanned` 表示完成 HTML 检查的页数，`pages_attempted`、`pages_failed`、`pages_skipped` 分别记录尝试、失败和跳过数量。


## 七、注意事项

1. 仅检测自己拥有或已经获得明确授权的网站。
2. 本工具不尝试绕过认证、WAF、访问控制或其他安全机制。
3. 检测结果会受到网络环境、代理、CDN、WAF、目标站点配置和证书链的影响。
4. 敏感路径检查仅使用内置的有限路径列表，路径存在不代表可被未授权访问。
5. 页面级检查受最大页数和最大深度限制，不能代表整个站点的完整审计结果。
6. `0.0.0.0`、`::` 以及 `224.0.0.0-255.255.255.255` 这类地址会被当作无效输入。
